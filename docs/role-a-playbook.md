# 角色 A 执行手册

角色 A 是产品负责人与 AI 主控，不是把全部工作抢过来做的人。A 的核心价值是缩小范围、定义验收、维持一条统一代码主线，并对最终演示负责。

## 1. A 必须先做的四个决定

1. 第一版只接一个真实来源、一个班级和五类页面：今日、未来七天、事项详情、项目库、提醒状态。
2. 第一版只做一条闭环：消息进入 → 原文保存 → 信息提取 → 去重更新 → 看板展示 → 截止提醒。
3. 对外接口先冻结为“标准化消息”和“结构化活动”两层，B/C/D/E 都围绕这两层工作。
4. 每个功能只有负责人实际运行并留下验收记录后才能合并；A 是唯一合并人和演示主控。

## 2. 第一周安排

| 日期 | A 要完成的事 | 验收证据 |
|---|---|---|
| 第 1 天 | 冻结 MVP 范围和不做清单 | 需求清单、验收表 |
| 第 2 天 | 确定消息 JSON、活动字段和状态机 | `app/schemas.py`、接口文档 |
| 第 3 天 | 建立后端、数据库和静态页面骨架 | 本地服务可启动 |
| 第 4 天 | 用固定样例打通解析和保存 | 至少 10 条解析测试 |
| 第 5 天 | 验证重复消息不重复建事项 | 幂等测试、数据库记录 |
| 第 6 天 | 完成看板、完成状态和提醒查询 | 电脑与手机浏览器可演示 |
| 第 7 天 | 接收 B–E 的结果并做首次联合验收 | 可回滚的 Git 提交、演示记录 |

## 3. A 给 AI 下任务的固定格式

每次只发一个纵向切片，不要把五人任务混成“一次做完整套软件”。

```text
请先阅读 README、docs/role-a-playbook.md 和当前代码，不扩大需求。

本次只实现：
[一个具体功能]

输入：
[一条脱敏通知或明确数据]

验收标准：
[可运行、可观察的结果]

请完成实现和测试，说明修改文件、验证命令、剩余风险。
没有实际运行的测试不要报告为通过。
```

## 4. 与 B–E 的接口

- B 交来真实平台消息样例、验签方式和触发条件；A 把它们转换成统一入口，不让平台字段渗入解析和前端。
- C 交来至少 50 条脱敏通知及标准答案；A 用它们做回归测试，不按单条样例反复修改特例。
- D 交来页面草图和跨端问题；A 维护 API 契约，避免页面直接依赖数据库字段。
- E 交来部署、备份和安全清单；A 在合并前检查密钥、个人信息和日志。

## 5. 每次合并前的检查

- 服务能启动，数据库可以初始化。
- 同一条 `platform + external_id` 只保存一次。
- 同一活动的新通知不会生成重复卡片。
- 不确定的截止时间标为“待核对”，不会静默猜一个日期。
- 原始通知和信息来源仍然可追溯。
- 所有新增测试实际通过。
- 提交里没有 Token、手机号、密码或真实学生通知。

## 6. A 的演示口径

演示按一条真实通知走完整流程，不先讲技术栈。展示原文、提取结果、同一活动延期后的合并结果，以及电脑与手机看到同一事项。最后再说明：机器人权限是产品边界，个人微信非官方 Hook 不进入正式主链路。
